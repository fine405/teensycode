# 7.3 Durable workflows

[Course lesson](https://vercel.com/academy/build-ai-agent-harness/durable-workflows)

An in-process `setTimeout` is not a lifecycle mechanism in serverless: the host
process may end after the request or be replaced by a deployment. A durable
workflow checkpoints `sleep()`, resumes in another process, and retries external
side effects at explicit step boundaries.

The cloud lifecycle loop should:

1. Sleep durably between polls.
2. Read fresh provider state in a retryable step.
3. Stop when the sandbox has expired.
4. Snapshot and stop once real activity is older than the inactivity window.

Local and just-bash sandboxes remain process-scoped and do not need this loop.
For a cloud backend, `afterStart` launches it and `beforeStop` requests a clean
shutdown through the same `Sandbox` surface.
