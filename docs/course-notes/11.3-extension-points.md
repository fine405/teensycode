# 11.3 Extension Points

The harness exposes five lifecycle events:

- `session_start`: initialize session-wide extensions.
- `tool_call`: log, modify, or block a tool before execution.
- `tool_result`: observe or modify a result after execution.
- `session_before_compact`: preserve instructions while pruning context.
- `session_shutdown`: checkpoint or clean up before the sandbox stops.

Handlers run in registration order. A pass-through handler returns nothing. A
`modify` result is merged into the event data before the next handler runs. The
first `block` stops the chain and its reason is returned to the model.

Approval and events are separate layers: tool approval decides whether a
command is operationally trusted, while an event policy can still reject an
otherwise approved call. The event bus complements the existing approval
configuration; it does not replace it.
