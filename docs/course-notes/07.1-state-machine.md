# 7.1 Sandbox state machine

[Course lesson](https://vercel.com/academy/build-ai-agent-harness/state-machine)

```text
provisioning -> active -> hibernating -> hibernated
                  ^                         |
                  +--------- restore -------+
```

- Hard expiry is provider-owned and cannot be extended; snapshot before it.
- The inactivity window is harness-owned and controls normal hibernation cost.
- User messages, tool calls, filesystem changes, and process starts are activity.
- Polling, reconnect probes, health checks, and billing reads are not activity.

The provider remains the lifecycle source of truth. A practical cloud backend
should warn and snapshot before hard expiry while avoiding false activity from
its own monitoring loop.
