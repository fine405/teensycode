# 7.2 Snapshot and restore

[Course lesson](https://vercel.com/academy/build-ai-agent-harness/snapshot-and-restore)

A snapshot preserves filesystem state, installed packages, and created files.
It does not preserve running processes, network connections, or in-memory work.
Restore creates a new sandbox from that filesystem checkpoint; setup hooks may
still need to reconcile project changes made after the snapshot.

Three operations must be idempotent:

1. Concurrent snapshot calls share one in-flight promise.
2. Restore first checks whether the session already has an active sandbox.
3. `stop()` records completion so later calls become no-ops.

Snapshots should be invalidated or followed by `afterStart` reconciliation when
the source revision, dependencies, or environment configuration has changed.
